# 제작 지침 (Build Guide)

Claude Code가 사이트를 만들 때 따르는 설계 문서. 원칙과 데이터 설명은 `CLAUDE.md`, 축과 점수 기준은 `docs/scoring.md`에 있다. 이 문서는 "무엇을 어떻게 그리는가"를 다룬다.

용어: **ACF** (Alternative Creative Platform, 구름 너머의 창작 플랫폼). 지도에 올라간 사례 하나하나를 가리킨다. 포함 기준은 `docs/scoring.md` 1장.

---

## 0. 핵심 개념: 같은 아이콘, 다른 배치

사이트의 중심은 **지도 한 화면**이다. ACF 26개의 아이콘은 늘 같고, 사용자가 고른 "보기"에 따라 **배치만 바뀐다.** 보기를 바꾸면 아이콘이 새 자리로 날아간다. "같은 사례가 기준에 따라 다른 자리에 놓인다"는 사이트의 주장을 화면 동작으로 보여 준다.

- **보기** (layout): 아이콘을 *어디에* 놓을지. 8분면 / 단면 / 한 줄 / 분류 / 지형도.
- **모아보기** (filter): *무엇을* 강조할지. 카테고리 칩. 해당하지 않는 아이콘은 흐려진다 (사라지지 않음).
- 둘은 독립적으로 겹쳐 쓴다. 예: "판매·유통만 켜고 8분면으로 보기".

## 1. 작업 순서

1. 페이지와 보기는 하나씩 만든다. 하나를 끝내고 사람이 확인한 뒤 다음으로 간다. 권장 순서:
   1. 빌드 스크립트 + JS 없이 읽히는 목록과 사례 페이지
   2. 지도: 8분면 보기 + 사례 카드
   3. 단면·한 줄 보기 (보기 전환 애니메이션)
   4. 모아보기 칩 + 분류 보기
   5. 지형도 보기 (관계 리서치 보강 후)
   6. /about, /reading, /credits
2. 데이터는 빌드 단계에서 CSV를 읽어 HTML과 `site/data.json`으로 내보낸다. 지도 JS는 이 JSON만 읽는다.
3. 새 데이터 열이 필요하면 지어내지 말고, 필요한 열과 이유를 사람에게 먼저 알린다. 아직 없는 열(아래 7장)은 빈 값으로 두고 화면에서 자연스럽게 생략한다.

## 2. 폴더 구조

```
outer-maps/
  CLAUDE.md
  CHANGELOG.md
  data/                 # CSV (유일한 원천, UTF-8 BOM)
  docs/                 # 리서치, 점수 기준, 이 문서
  build/
    build.mjs           # CSV → HTML + data.json (Node, 의존성 최소)
  src/
    templates/          # HTML 조각
    css/site.css
    js/map/             # 지도: scene.js, layouts.js, card.js, controls.js
    vendor/three/       # three.js 모듈 파일을 직접 복사해 둠 (CDN 금지)
    icons/              # ACF 아이콘 SVG (직접 그림, id.svg)
    fonts/              # 자체 호스팅 서체 (OFL)
  site/                 # 빌드 결과 (Neocities / Codeberg Pages에 그대로 올림)
```

- `build.mjs`는 Node 기본 모듈과 작은 CSV 파서 하나만 쓴다. 번들러, 프레임워크 금지. three.js는 ES 모듈 그대로 `<script type="module">`과 import map으로 불러온다.
- CSV를 읽을 때 BOM(`﻿`)을 제거한다. CSV를 쓸 때는 BOM을 붙이고 CRLF로 저장한다.
- 빌드 검사: `score_*` 값이 0~3인지, `relations.csv`의 `source`/`target` id가 존재하는지, `category` 값이 정해진 목록 안인지, `src/icons/{id}.svg`가 있는지(없으면 경고만, 이니셜 원판으로 대체). 오류면 빌드를 멈춘다.

## 3. 페이지 목록

```
/                지도 (보기 5 + 모아보기 + 사례 카드) + 같은 내용의 목록

/about/          왜 세 축인가 · 포함 기준 · 세 개의 층 · 점수 기준
/reading/        읽을거리

```

## 4. 지도 화면 (메인)

### 4-1. 레이아웃

```
┌─────────────────────────────────────────┐
│ Outer Maps            소개 · 읽을거리 · ☰ │  헤더
├─────────────────────────────────────────┤
│ 보기   8분면 · 단면 · 한 줄 · 분류 · 지형도 │  보기 전환 (세그먼트 버튼)
│ 모아   전체 · 창작 도구 · 판매·유통 · …     │  모아보기 칩 (여러 개 선택 가능)
│        └ 이미지 · 영상 · 애니 · 사운드 …   │  창작 도구 하위 칩 (선택 시 펼침)
├─────────────────────────────────────────┤
│                                         │
│        지도 캔버스 (three.js)             │
│                                         │
│  연대 ↑                    ⓘ 왜 이 세 축? │
│     └── 참여 →                           │
└─────────────────────────────────────────┘
  사례 카드: 데스크톱 = 오른쪽 패널 / 모바일 = 아래 시트
  ─────────────────────────────────────────
  목록 (지도와 같은 내용, 현재 모아보기 반영, JS 없어도 보임)
```

### 4-2. 다섯 가지 보기

| 보기 | 배치 | 카메라 | 조작 |
|---|---|---|---|
| **8분면** (기본) | x 참여 · y 독립 · z 연대 (정의: `scoring.md` 3장). 중심 1.5로 8칸 | 원근 | 드래그 회전, 휠·핀치 확대 |
| **단면** | 세 축 중 두 개를 골라 2D 평면 | 정사영, 정면 | 축 두 개 선택 |
| **한 줄** | 축 하나를 골라 0~3 띠 위에 줄 세움 | 정사영 | 축 하나 선택 |
| **분류** | `category`별 묶음 (구획 + 구획 이름) | 정사영 | — |
| **지형도** | 평면: 위에 Adobe 구름, 아래 ACF, 관계선 | 정사영 | 관계 종류 토글 |

- 단면·한 줄·분류·지형도의 축 선택기에서는 다섯 축(소유, 재정, 개방성, 참여, 연대) 모두 고를 수 있다. 8분면도 고급 옵션으로 세 축을 바꿀 수 있다.
- **전환 애니메이션**: 보기가 바뀌면 아이콘이 0.8초 동안 새 좌표로 보간한다. 8분면 → 단면 → 한 줄은 "입체가 납작해지는" 느낌이 나게, 사라지는 축의 값을 0으로 누르면서 카메라를 정사영으로 바꾼다.
- 보기 상태는 URL 해시에 남긴다 (`#view=slice&x=community&y=solidarity&filter=sale`). 공유와 뒤로 가기를 위해서.

### 4-3. 아이콘 (스프라이트)

- 각 ACF는 `THREE.Sprite` (늘 카메라 정면을 봄). 텍스처는 `src/icons/{id}.svg`를 캔버스에 그려 만든다. 아이콘이 없으면 이름 이니셜을 넣은 원판.
- 크기는 화면 기준 일정하게 (`sizeAttenuation`을 끄거나 거리 보정). 너무 작아지지 않게.
- 층 표기: `grey`는 ◐ 배지, `contrast`는 점선 테두리 + "대조" 라벨. 색에만 의존하지 않는다.
- **겹침**: 같은 좌표의 아이콘들은 그 점 주변에 작은 원형이나 격자로 고르게 배치한다. id 순서로 결정적으로 계산해 새로 고침해도 같은 자리에 있게 한다. 무작위로 흩뜨리지 않는다.
- 모아보기에서 빠진 아이콘은 opacity 0.15, 상호작용 불가.

### 4-4. 축과 칸 라벨

- 축 끝에 HTML 라벨 (`CSS2DRenderer`): 축 이름 + 한 줄 ("참여 → 소비 ↔ 공동 제작").
- 8분면의 각 칸 모서리에 칸 이름 (`scoring.md` 3장). 빈 칸도 이름을 보여 준다.
- 축 라벨이나 ⓘ를 누르면 **"왜 이 세 축인가"** 패널: 다섯 질문 → 세 축으로 고른 이유, 각 축의 0~3 기준 요약, 포함 기준과 세 층. 전체 글은 `/about/`으로 링크.

### 4-5. 사례 카드

```
┌──────────────────────────────┐
│ [아이콘]  Krita                │
│ 디지털 페인팅 · 창작 도구        │
│ 한 줄 소개 (tagline)            │
│ 참여 ███ 독립 ███ 연대 ██░      │  지문 글리프 + 숫자
│ GPL · 기부·개발 기금            │
│ [공식 사이트] [다운로드] [자세히 →] │
└──────────────────────────────┘
```

- **데스크톱**: 호버하면 미리보기(작은 말풍선), 클릭하면 오른쪽 패널에 카드를 고정.
- **모바일**: 탭하면 아래에서 반쯤 올라오는 시트. 위로 끌면 전체 펼침. 다른 곳을 탭하거나 아래로 끌면 닫힘.
- 다운로드 버튼은 `download_url`이 있을 때만. 없으면 공식 사이트만.
- "자세히 →"는 `/acf/{id}/`.

### 4-6. 조작과 접근성

- 마우스: 드래그 회전, 휠 확대. 터치: 한 손가락 회전, 두 손가락 핀치 확대.
- **모바일 스크롤 충돌**: 캔버스 위 터치는 기본으로 페이지 스크롤에 양보한다. "둘러보기" 버튼을 누르면 회전 모드가 켜지고(`touch-action: none`), 다시 누르거나 카드를 닫으면 꺼진다.
- 키보드: 화살표 키로 회전, Tab으로 아이콘 사이 이동 (캔버스 위에 보이지 않는 버튼 목록을 겹쳐 두고, 포커스 위치에 테두리를 그린다), Enter로 카드 열기, Esc로 닫기.
- 가만히 있으면 아주 천천히 자동 회전. `prefers-reduced-motion`이면 자동 회전과 전환 애니메이션을 끄고 즉시 배치.
- 성능: `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, 화면 밖이거나 탭이 숨으면 렌더 루프 정지, 움직임이 없으면 다시 그리지 않음.
- 목표 용량: three.js 제외한 지도 JS 30KB 이하. three.js는 필요한 모듈만 (`three.module.js`, `CSS2DRenderer`, `OrbitControls`).

### 4-7. JS가 없을 때

- 지도 자리에 빌드 단계에서 그린 **8분면의 정적 SVG** (아이소메트릭) 한 장.
- 아래 목록은 항상 HTML로 존재: 이름, 카테고리, 세 축 점수, 속한 칸 이름, `layer`, 사례 페이지 링크.
- 모아보기 칩은 JS가 없으면 목록 위의 앵커 링크(카테고리별 소제목)로 대체.

## 5. 지형도 보기 상세

- 평면 배치. 위쪽에 Adobe 구름(`nodes_external.csv`의 `cloud-tool`, `cloud-service`), 그 아래로 각 구름 노드의 대안이 매달린다 (`cloud_counterparts`, `alternative_to`). 기업 노드(Canva, Muse Group, Meta 등)는 옆쪽에.
- 관계 종류마다 선 모양을 다르게: 대안(가는 실선), 인수·소유(굵은 화살표), 포크(점선 화살표), 커뮤니티 소속(이중선), 함께 쓰기(점선), 대조(물결선). 범례 필수.
- 관계 종류 토글. `alternative_to`는 기본으로 켜고, 나머지는 하나씩 켜 볼 수 있게.
- Cavalry처럼 `contrast`인 사례는 구름 바로 아래, 구름에 붙여 둔다.
- **리서치 보강 필요** (`relations.csv`에 추가할 관계 종류 후보): 같은 우산 조직(KDE, GNU, Software Freedom Conservancy, 연합우주), 파일 포맷 호환(GIMP ↔ Krita OpenRaster 등), 후원·공공 기금(Blender 개발 기금, NLnet/NGI), 포크 계보(enve → Friction, Audacity → Tenacity). 새 관계 종류를 추가하면 `CLAUDE.md`의 관계 목록과 범례를 함께 고친다.

## 6. 사례 페이지 `/acf/{id}/`

- 정적 HTML. 아이콘, 이름, 한 줄 소개, 카테고리, 라이선스(무료의 근거가 라이선스인지 회사 정책인지 명시), 재정, 다섯 축 점수와 지문 글리프, 속한 8분면 칸, 연대 근거(`solidarity_evidence.csv`, 확신도 "낮음"인 0점은 "근거를 못 찾음"으로 표기), 지속 가능성과 한계, 관련 관계, 출처.
- **지문 글리프**: 다섯 축 점수를 짧은 막대 다섯 개로. 텍스트 대체("소유 3 · 재정 3 · 개방 3 · 참여 3 · 연대 1")를 함께 둔다. 레이더 차트는 쓰지 않는다.
- 페이지 아래에 "지도에서 보기" 링크 (`/#focus={id}`).

## 7. 추가가 필요한 데이터 열 (`platforms.csv`)

| 열 | 뜻 | 상태 |

## 8. 디자인 지침

서체, 색, 카드·알약·아이콘 형태, 글자 크기, 움직임은 **`docs/design-guide.md`**에 따로 있다. 코드에서는 그 문서의 CSS 토큰(`--bg`, `--ink`, `--accent`, `--fs-*`)을 그대로 쓰고, 값을 하드코딩하지 않는다. 모바일 우선: 360px 폭에서 먼저 설계하고 넓혀 간다.

## 9. 성능·접근성 체크리스트 (보기·페이지마다)

- [ ] JS를 꺼도 핵심 정보(목록, 사례 페이지)가 읽힌다
- [ ] 360px 모바일에서 가로 스크롤 없음, 카드 시트가 정상 동작
- [ ] 첫 화면 용량 (서체·three.js 제외) 200KB 이하 목표
- [ ] 외부 스크립트, CDN, 추적, 분석 없음
- [ ] 키보드만으로 보기 전환, 아이콘 선택, 카드 열고 닫기 가능
- [ ] 색 없이도 구분 가능
- [ ] `prefers-reduced-motion` 존중
- [ ] 시각화와 같은 내용의 목록이 있음
- [ ] "확인 필요" 값은 추측으로 채우지 않고 그대로 보이거나 비어 있음
